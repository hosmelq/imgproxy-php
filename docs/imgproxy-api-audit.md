# imgproxy public API coverage audit

Audit date: 2026-10-20. This document records the pinned public contract, the original review findings and their implemented corrections. No server deployment is part of this package.

Baseline: **imgproxy v4.0.18**, released 2026-10-14 ([release](https://github.com/imgproxy/imgproxy/releases/tag/v4.0.18)); official **4.0.x** documentation pinned to commit `8d30510b5e7216691f8d155bca78351927ec3b1b`. The unversioned `docs/` directory describes upcoming features and is listed separately. The public Pro contract is checked against first-party documentation; proprietary Pro runtime code was not available for execution.

Current local surface: **84 processing option families and 32 info option families**. Stable official surface: **84 processing option families**, **32 info option families**, URL structure/signing/encryption, presets and chained pipelines, request-header features, source adapters, and server configuration. Matching an option name does not establish that all arguments, defaults and serialization are compatible.

## Corrected findings

All stable URL-generation findings below are implemented. The final reproduction section records the original behavior at commit `09402c4`; regression tests now cover the corrected behavior. Pro serialization follows the public contract, while live Pro transformations require a licensed server.

| Priority | Original finding | Implemented behavior |
| --- | --- | --- |
| P1 | Source encryption applies PKCS#7 padding twice and fails the official known vector. | Apply padding once; one standard decryption must recover the exact source URL. |
| P1 | Options with all-null arguments serialize without `:` and are interpreted as the source URL. | Preserve valid empty argument syntax; reject invalid empty lists. |
| P1 | Alphabetical option ordering changes precedence between meta-options, individual options and presets. | Preserve the meaning and precedence of the configured operations. |
| P1 | No first-class info option namespace; processing `size`/`format` have incompatible meanings. | Support all 32 stable info families and their signed endpoint grammar. |
| P2 | Missing `blur_areas`, `crop_objects` and `preserve_hdr`. | Add the three stable option families and their arguments. |
| P2 | Integer-only types reject decimal autoquality targets, unsharp dividers, resolution limits and trim thresholds; padding wrongly accepts fractions. | Match each argument's actual numeric domain. |
| P2 | Optional/reset forms, custom separators, presets-only mode and chained pipelines are incomplete. | Represent every valid stable URL form, including repeated names in separate pipelines. |
| P2 | Profile filenames and arbitrary cache-buster strings have no safe, explicit escape contract. | Encode or validate argument data before building and signing the URL. |
| P2 | No SEO source-filename suffix option; six secondary aliases cannot be selected. | Support filename mode where configured; account for alias-specific server allowlists. |
| Scope | 283 documented IMGPROXY settings plus eight source-only controls are inventoried below. | Keep URL-builder settings and server/deployment settings distinct; server settings are not processing options. |

Signed URLs were exercised locally against the official imgproxy v4.0.18 OSS image, including custom separators, presets-only mode, source chunking, SEO filenames, numeric limits, empty/reset arguments, effective resize precedence and tampered-signature rejection. That temporary Docker harness is not part of the package or CI. No licensed Pro server was exercised.

### Processing argument domains and special forms

These rules are part of the API surface, in addition to the signatures above. Each item links to its owning option definition.

- **`resizing_type`**: * `fit`: resizes the image while keeping aspect ratio to fit a given size.; * `fill`: resizes the image while keeping aspect ratio to fill a given size and crops projecting parts.; * `fill-down`: the same as `fill`, but if the resized image is smaller than the requested size, imgproxy will crop the result to keep the requested aspect ratio.; * `force`: resizes the image without keeping the aspect ratio.; * `auto`: if both source and resulting dimensions have the same orientation (portrait or landscape), imgproxy will use `fill`. Otherwise, it will use `fit`. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L73)
- **`extend`**: * When `extend` is set to `1`, `t` or `true`, imgproxy will extend the image if it is smaller than the given size.; * `gravity` _(optional)_ accepts the same values as the gravity option, except `sm`, `obj`, and `objw`. When `gravity` is not set, imgproxy will use `ce` gravity without offsets. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L198)
- **`extend_aspect_ratio`**: * When `extend` is set to `1`, `t` or `true`, imgproxy will extend the image to the requested aspect ratio.; * `gravity` _(optional)_ accepts the same values as the gravity option, except `sm`, `obj`, and `objw`. When `gravity` is not set, imgproxy will use `ce` gravity without offsets. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L210)
- **`gravity`**: * `type` - specifies the gravity type. Available values:; * `no`: north (top edge); * `so`: south (bottom edge); * `ea`: east (right edge); * `we`: west (left edge); * `noea`: north-east (top-right corner); * `nowe`: north-west (top-left corner); * `soea`: south-east (bottom-right corner); * `sowe`: south-west (bottom-left corner); * `ce`: center; * `x_offset`, `y_offset` - (optional) specifies the gravity offset along the X and Y axes:; * When `x_offset` or `y_offset` is greater than or equal to `1`, imgproxy treats it as an absolute value.; * When `x_offset` or `y_offset` is less than `1`, imgproxy treats it as a relative value.; * `gravity:sm`: smart gravity. `libvips` detects the most "interesting" section of the image and considers it as the center of the resulting image. Offsets are not applicable here.; * `gravity:obj:%class_name1:%class_name2:...:%class_nameN`: Pro object-oriented gravity. imgproxy detects objects of provided classes on the image and calculates the resulting image center using their positions. If class names are omited, imgproxy will use all the detected objects. Also, you can use the `all` pseudo-class to use all the detected objects.; * `gravity:objw:%class_name1:%class_weight1:%class_name2:%class_weight2:...:%class_nameN:%class_weightN`: Pro object-oriented gravity with weights. The same as `gravity:obj` but with custom weights for each class. You can use the `all` pseudo-class to set the weight for all the detected objects. For example, `gravity:objw:all:2:face:3` will set the weight of all the detected objects to `2` and the weight of the detected faces to `3`. The default weight is `1`.; * `gravity:fp:%x:%y`: the gravity focus point. `x` and `y` are floating point numbers between 0 and 1 that define the coordinates of the center of the resulting image. Treat 0 and 1 as right/left for `x` and top/bottom for `y`. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L223)
- **`objects_position`**: * `type` - specifies the position type. Available values:; * `no`: north (top edge); * `so`: south (bottom edge); * `ea`: east (right edge); * `we`: west (left edge); * `noea`: north-east (top-right corner); * `nowe`: north-west (top-left corner); * `soea`: south-east (bottom-right corner); * `sowe`: south-west (bottom-left corner); * `ce`: center; * `x_offset`, `y_offset` - (optional) specifies the position offset along the X and Y axes.; * `objects_position:fp:%x:%y`: the focus point position. `x` and `y` are floating point numbers between 0 and 1 that define the coordinates of the center of the objects' area in the resulting image. Treat 0 and 1 as right/left for `x` and top/bottom for `y`.; * `objects_position:prop`: the proportional position. imgproxy will try to set object offsets in the resulting image proportional to their offsets in the original image. This position type allows the picture scene to be maintained after cropping. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L255)

## URL, signing, encryption, presets and pipelines

- Processing URL grammar is `/{signature}/{options}/plain/{source}@{extension}`, `/{signature}/{options}/{base64-source}.{extension}`, or `/{signature}/{options}/enc/{encrypted-source}.{extension}`. Signature is always present; arbitrary placeholders are allowed only when signature validation is disabled. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L13)
- The signature is unpadded URL-safe Base64 of HMAC-SHA256(key, salt + exact path after signature, including its leading slash), optionally truncated to `IMGPROXY_SIGNATURE_SIZE` bytes before Base64 encoding. Server `IMGPROXY_PATH_PREFIX` and `/info` route prefix are outside the signed suffix. Multiple server key/salt pairs permit rotation; a client signs with one active pair. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/signing_url.mdx); [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/configuration/options.mdx#L9)
- Plain sources are percent-encoded; at minimum `%`, `?`, and `@` must be escaped in that order. Base64 source and encrypted Base64 source may be split across slash-separated chunks. Output format extension is optional. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/processing.mdx#L1243)
- Source encryption is Pro AES-CBC with a 16/24/32-byte hex-decoded key, exactly one PKCS#7 padding layer, a 16-byte IV, and unpadded URL-safe Base64 of IV + ciphertext. Random/cached or deterministic HMAC-derived IV strategies are documented. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/encrypting_source_url.mdx)
- Processing and info options share configurable `IMGPROXY_ARGUMENTS_SEPARATOR` (default `:`). Presets use `IMGPROXY_PRESETS`, `IMGPROXY_PRESETS_PATH`, and `IMGPROXY_PRESETS_SEPARATOR`; a `default` preset applies to every image. A URL can apply multiple presets. Presets-only mode replaces ordinary option syntax with `{preset1}:{preset2}:...`; info has a separate inherited/overridable mode. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/usage/presets.mdx); [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/configuration/options.mdx#L529)
- Pro chained pipelines use a standalone `/-/` path segment. A pipeline may reuse option names independently. Presets can contain pipelines, and preset/URL pipelines are merged according to the documented rules; a single associative option map cannot represent this contract. [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/features/chained_pipelines.mdx)

## CLI commands and configuration entry points

The v4.0.18 executable registers `imgproxy` (start server), `imgproxy version` (print version), and `imgproxy health` (HTTP healthcheck; exit 0/1). Configuration is loaded from ENV and supported ENV loading providers; there is no separately documented `--width`, `--resize`, or flag-per-server-option API. Framework help commands/options are generated by the CLI library. [source](https://github.com/imgproxy/imgproxy/blob/v4.0.18/cli/main.go); [source](https://github.com/imgproxy/imgproxy/blob/v4.0.18/cli/healthcheck.go); [source](https://github.com/imgproxy/imgproxy-docs/blob/8d30510b5e7216691f8d155bca78351927ec3b1b/versioned_docs/version-4.0.x/configuration/loading_environment_variables.mdx)

The Free v4 Go package also exposes embeddable configuration/instance APIs (`Init`, `Shutdown`, `NewDefaultConfig`, `LoadConfigFromEnv`, `New`, `BuildRouter`, `StartServer`, `Close`); these are Go embedding interfaces rather than PHP URL methods. [source](https://github.com/imgproxy/imgproxy/blob/v4.0.18/config.go); [source](https://github.com/imgproxy/imgproxy/blob/v4.0.18/imgproxy.go)

## Implemented compatibility and evidence limits

- All 84 stable processing families and all 32 stable info families have fluent methods, with canonical, short and secondary aliases.
- Ordered options, repeated presets, chained processing pipelines, presets-only mode, custom separators and supported source encodings are implemented.
- AES padding, numeric parameter domains, reset/omitted arguments, extension gravity, short hex colors and escaped argument data are corrected.
- Official HMAC/AES vectors and exact AES round trips are covered by Pest regressions. Local OSS server checks confirmed the relevant parser and resulting-image behavior.
- PHP 8.4+ is the supported runtime. CI tests PHP 8.4 and 8.5; quality checks use the existing Composer/Pest/Pint/Rector/PHPStan/dependency-analyser patterns.
- Server-only ENV variables remain an independently documented deployment contract. The package generates URLs and does not deploy servers, send requests or parse image-info responses.
- Upcoming options remain separate from the supported stable release. Source-only controls and deprecated server aliases are labeled.
- Live licensed Pro transformation checks remain unavailable; public docs establish the serialized Pro contract, not runtime proof.

## Additional builder configuration

Both builders share source encoding, encryption, signature, separator, alias, source-chunk and source-filename configuration through the existing fluent concern pattern. `trustedSignature(null)` restores HMAC signing or the unsigned default. Direct constructors validate key length, IV length, source-chunk length and option namespace where applicable.

`cachebuster()` uses URL-safe Base64 for opaque cache-key values, so reserved characters cannot alter the path or collide with imgproxy's normalization of `%3A`. Profile filenames are percent-encoded. Filename values containing colons automatically use the protocol's Base64 form unless the caller explicitly requests escaped form, which must satisfy the server argument grammar.

## Historical findings at baseline 09402c4

The original implementation double-padded AES-CBC plaintext, producing an extra ciphertext block and leaving padding bytes after standard decryption. The current implementation matches the official encryption vector and round-trips the exact source URL.

The original methods rejected documented decimal values for autoquality targets, unsharp dividers, source-resolution limits and trim thresholds, while accepting fractional padding that the server rejects. Optional resize arguments, background/trim resets, extension gravity and three-digit colors were incomplete. Those argument domains and forms are now supported.

Options with all-null arguments previously lost the required separator, causing the server to interpret them as source URLs. Alphabetical ordering also changed precedence between meta-options, individual options and presets. Current serialization retains valid empty arguments, rejects invalid empty lists and preserves call order.

Raw profile and cache-buster values could change URL grammar. Profile filenames are now escaped and opaque cache-buster values use URL-safe Base64. The old snapshots used undocumented autoquality and unsharp methods; the updated examples use documented values. `format()` previously emitted both an option and a final extension; it now emits only the ordered option, with an explicit build extension taking final precedence.
